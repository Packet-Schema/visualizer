# Git ワークフロー

Git 操作が必要な場合は、ユーザーや他作業者の変更を壊さないことを最優先にします。

## 事前確認

1. `git status` や `git diff` で既存差分を確認する。
2. 自分の作業と無関係な差分は戻さず、そのまま扱う。
3. 自分の作業対象と衝突しそうな差分がある場合は、作業を止めてユーザーに確認する。
4. 変更種別がフロントエンドかバックエンドかにかかわらず、`web` 配下やその生成物・関連設定に触れる変更が含まれる場合は、Git 操作の前に `run-format` を通して整形差分の有無を確認する。

## ブランチ

新しくブランチを切る場合は、内容に応じて次の形式を目安にします。

- `feat/<short-slug>`
- `fix/<short-slug>`
- `docs/<short-slug>`
- `refactor/<short-slug>`
- `test/<short-slug>`
- `chore/<short-slug>`

## コミット

コミットメッセージに厳密な規約はありません。変更内容が読みやすく伝わる短い要約を優先します。

コミット前には、差分と検証結果を確認し、意図しないファイルが含まれていないかを見るようにします。
コミット対象に `web` 配下やその生成物・関連設定の変更がある場合は、少なくとも `run-format` を先に実施し、必要なら整形後の差分で再確認します。

## PR 準備

PR を作る前提の変更では、次を説明できる状態に整理します。

- 関連 issue
- 変更点
- テスト方法や確認結果
- 未実施の検証がある場合の理由

PR 準備時も、整形差分が残っていないことを前提に整理します。

PR を作成するときは `.github/PULL_REQUEST_TEMPLATE.md` を参照し、記載項目に沿って内容を整理します。
